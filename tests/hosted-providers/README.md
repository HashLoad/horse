# Hosted provider regression tests

These tests make real HTTP requests; successful compilation alone is not a pass.
`check-http.py` verifies status/body, a custom response header, single query/form
decoding, UTF-8 JSON bodies and a missing route. Every supported case runs with
both Tree and Radix. Reports belong under ignored `benchmarks/results/`.

## Apache, CGI and FastCGI with FPC / Linux

The Dockerfile needs an existing local `fpc-test:latest` image with FPC 3.2.2 and
a compatible Debian base. This is a local prerequisite, not a published image.
Build the stable image and the pinned development compiler separately:

```powershell
docker build --target bootstrap -t horse-provider-tests:fpc-3.2.2 -f tests/hosted-providers/Dockerfile.fpc-trunk .
docker build -t horse-provider-tests:fpc-3.3.1 -f tests/hosted-providers/Dockerfile.fpc-trunk .
$output = (New-Item -ItemType Directory -Force benchmarks/results/hosted-local).FullName
$repo = (Get-Location).Path
docker run --rm --mount "type=bind,source=$repo,target=/repo,readonly" --mount "type=bind,source=$output,target=/out" --entrypoint bash horse-provider-tests:fpc-3.3.1 /repo/tests/hosted-providers/run-apache-hosted.sh
```

Repeat with the stable image and a **different output directory**. No port is
published on the host: Apache uses 19280 and FastCGI 19281/19282 inside the container.
Tree and Radix use separate FastCGI ports to avoid TIME_WAIT bind collisions.
The repository mount is read-only. Do not edit the mounted scripts while they
are running. For targeted runs pass `-e "HORSE_TEST_PROVIDERS=CGI FastCGI"`;
this deliberately excludes Apache-module coverage and must not be reported as
an all-provider pass.

The FastCGI test binds `0.0.0.0` **inside the isolated container**, with no host
port publication. Its Apache configuration selects `GENERIC` backend handling
and explicitly maps `SCRIPT_NAME` to `PATH_INFO`; `ProxyPass` does not generate
`PATH_INFO` by default. See the official
[Apache FastCGI documentation](https://httpd.apache.org/docs/2.4/mod/mod_proxy_fcgi.html#proxyfcgisetenvif).

Run `run-keepalive.sh` in the same image/mount layout for FPC 3.3.1. It asserts
HTTP 200 and reuse of the same socket for 30 requests, with a latency threshold.

### Isolating external Apache failures

`check-fpc-apache-baseline.sh` compiles `FpcApacheBaseline.lpr`, which imports
**no Horse units**. Run it in the same image/mount layout when Apache crashes.
The baseline is diagnostic, not an expected-failure exemption or a passing
Horse regression test. `Dockerfile.debug` supplies GDB in a disposable image.

On 2026-10-06, Apache 2.4.68 / Debian failed with both FPC 3.2.2 and the pinned
3.3.1 compiler, including this baseline. A 3.3.1 backtrace reaches
`SYSTEM ... THREADSTATE.ORPHAN` through `CTHREADCLEANUP` while the Apache FPC
runtime's dummy thread is active. Keep this limitation explicit: Apache-module
runtime validation is **not green** in this environment. Do not patch external
FPC/Apache libraries to hide it or infer that Horse caused the crash.
The optional `-e BASELINE_CMEM=1` baseline experiment also reproduced the
failure; changing only the fixture's memory-manager selection did not resolve it.

## CGI and ISAPI with Delphi / Windows

Use a trusted Microsoft IIS Express **x86** runtime for the Win32 DLL/EXE
matrix. A portable administrative extraction of the signed official MSI under
`benchmarks/results/iis-express-runtime/` is sufficient; installing/enabling
system IIS, Windows containers or changing machine configuration is unnecessary.

```powershell
pwsh -File tests/hosted-providers/run-iis-hosted.ps1 -RuntimeRoot 'D:/Delphi/horse/benchmarks/results/iis-express-runtime/extracted/IIS Express'
```

Requires Python and the local Delphi compilers. The runner uses its own
applicationhost.config, site, user-home and process; it restores environment
variables and stops only its own IIS Express process. Port 19280 must be free
(`-Port` can override it). It intentionally permits only the fixture handler
in this isolated host. Do not copy these permissive test restrictions into a
production IIS configuration. CGI fixtures must be console applications.
JSON responses explicitly declare `application/json; charset=utf-8`.

The host process is stopped after each case: this does **not** prove graceful
application shutdown or leak freedom inside a production worker process.

## Delphi Apache / Linux

Run `pwsh -File tests/hosted-providers/run-delphi-apache.ps1` for the locally
installed Delphi 12/13 Linux compilers, each with Tree and Radix. The test
mounts the application at `/horse` through an Apache Alias, preserving the
route suffix as `PATH_INFO`.

`link-and-run-delphi-apache.sh` consumes `HostedProviderCheck.lnk/.vsr` and
objects generated by `dcclinux64 --save-temps -DHORSE_APACHE`, mounted at `/out`.
Mount the corresponding installed Delphi `lib/linux64/release` at `/delphi`
read-only, and the repository at `/repo` read-only. It uses the container's
native linker and Apache. Keep compiler version and Tree/Radix output separate.
An attempted or linked build is not a runtime pass: require `results.log` and a
zero exit status from the HTTP checks.
